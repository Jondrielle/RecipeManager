# 🍳 Recipe Manager

A full-stack recipe management application built with **Vue 3**, **FastAPI**, **SQLModel**, and **SQLite**.

Recipe Manager allows users to create, view, edit, and delete recipes through a responsive web interface backed by a REST API and persistent database.

## 🏗️ Architecture

The application is split into a Vue frontend and FastAPI backend.

```text
┌─────────────────────┐
│     Vue 3 Frontend  │
│       Netlify       │
└──────────┬──────────┘
           │
           │ HTTP / JSON
           ▼
┌─────────────────────┐
│    FastAPI Backend  │
│       Render        │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│   SQLModel / SQLite │
│      Database       │
└─────────────────────┘
```

The frontend communicates with the FastAPI backend using HTTP requests. FastAPI handles validation, database operations, and API responses.

## 🔌 API Endpoints

| Method   | Endpoint        | Description          |
| -------- | --------------- | -------------------- |
| `GET`    | `/`             | Retrieve all recipes |
| `POST`   | `/recipe`       | Create a recipe      |
| `PATCH`  | `/recipes/{id}` | Update a recipe      |
| `DELETE` | `/recipe/{id}`  | Delete a recipe      |

The API uses JSON for request and response data.

## 🗄️ Database

Recipe data is stored using **SQLModel** with SQLite.

Each recipe contains information such as:

```text
Recipe
├── id
├── name
├── description
├── ingredients
├── instructions
├── prep_time
├── cook_time
├── servings
├── difficulty
└── image_url
```

Recipe IDs are automatically generated by the database.

Ingredients and instructions are stored as structured JSON data within the recipe record.

## ✅ Validation

Recipe data is validated on the backend using **Pydantic/SQLModel**.

Examples of validation include:

* Recipe names must contain valid text and have length limits.
* Preparation and cooking times cannot be negative.
* Serving sizes must be greater than zero.
* Difficulty must use a valid difficulty value.
* Ingredients must contain the expected name, amount, and unit fields.

The frontend displays an error message when an API request fails.

## 🖼️ Recipe Images

Recipes can include an image using an image URL.

The application expects an image resource URL rather than a webpage URL.

For example:

```text
https://example.com/recipe-image.jpg
```

The image is then displayed as part of the recipe.

## 💻 Running Locally

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd recipe-manager
```

### 2. Start the backend

Navigate to the backend directory:

```bash
cd backend
```

Install dependencies with `uv` and start the FastAPI server:

```bash
uv sync
uv run uvicorn main:app --reload
```

The API will be available at:

```text
http://localhost:8000
```

### 3. Start the frontend

Open another terminal and navigate to the frontend:

```bash
cd frontend
```

Install the frontend dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Vite will provide a local development URL, typically:

```text
http://localhost:5173
```

## 🚀 Deployment

The frontend and backend are deployed separately.

### Frontend — Netlify

The Vue application is built using Vite:

```bash
npm run build
```

The resulting `dist` directory is served by Netlify as a static site.

### Backend — Render

The FastAPI application runs as a Render Web Service.

Production start command:

```bash
uv run uvicorn main:app --host 0.0.0.0 --port $PORT
```

The deployed frontend communicates with the deployed FastAPI API rather than the local development server.

## ⚠️ Known Limitations

This project was built to practice full-stack development and CRUD operations. The current version focuses on core functionality, and some features have been intentionally left out to keep the project manageable while learning.

- **No user authentication:** Recipes are not associated with individual user accounts.
- **Basic image handling:** Recipe images are added through URLs. The application does not support direct image uploads or image hosting.
- **Limited search and filtering:** Recipes cannot currently be searched or filtered by ingredients, categories, or difficulty.
- **Basic recipe organization:** There are no categories, favorites, or personalized recipe collections.
- **SQLite database:** The application uses SQLite for simplicity. A different database may be more suitable as the application grows.
- **Limited automated testing:** Test coverage can be expanded to verify frontend behavior and backend API operations.

These limitations are known and are not all planned for immediate implementation. The priority is to understand the fundamentals of Vue 3, FastAPI, REST APIs, data validation, and database operations before introducing additional complexity.
